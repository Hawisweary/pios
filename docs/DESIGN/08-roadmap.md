# 08 · Roadmap

## 四阶段（严格反对一次建 12 层）

| 阶段 | 时间 | 交付 | 里程碑判据 |
|---|---|---|---|
| **Phase 0** | 2 周 | 仓库 + 事件流 + 手写 profile + BCIC 第一门课 + Mentor 每日 briefing + decision/idea/experiment 模板 | **连续 14 天早上收到 briefing 并照做** |
| **Phase 1** | 第 1 学期 | GitHub/论文/课程 collector + Skill Engine v1（证据深度×多样性）+ FSRS + 周报 + 月度抽测 + proposal 审批回路 | 一周内零手动录入（日记除外）；技能分数经过一次抽测校准 |
| **Phase 2** | 第 2 学期 | 夜间 Reflection Pass（reschedule/merge_idea/exploration）+ Capability 聚合 + Twin gap 分析 | briefing 出现图谱推理式建议 |
| **Phase 3** | 第 2 年起 | Time Machine 时间轴 + Calibration 曲线 + Investment/Career 投影 + Dashboard | Twin 匹配度曲线跨学期可比 |

**Phase 0 判据是整个项目最重要的一行**：最简版 briefing 你自己都不看，后面 11 层建了也没人用。
先证明闭环成立，再加复杂度。

## GUI 触发条件（不按日期，按"数据配得上界面"）

- **只读状态页**：随时可做（纯投影，删掉零损失）。
- **Proposal 审批界面**：当 Reflection Pass 每天产生 ≥3 条提案、文本裁决开始有摩擦时。
- **完整 Dashboard**：三条件缺一不可——≥1 学期几千条事件 / 引擎已在 CLI 跑通并经月度校准 /
  briefing 习惯已稳定。倒过来先做漂亮 Dashboard 是这类项目最常见的死法。

## 成功标准与死亡陷阱

五个成功标准（完整性/可解释性/持续使用/成长价值/长期可迁移）与四个死亡陷阱
（元工作/手动录入死亡螺旋/数字自欺/过度工程/好奇心被调度器接管）详见
[../PRINCIPLES.md](../PRINCIPLES.md)。每个成功标准必须由 PIOS 自动计算、出现在每月 Review 里，
否则四年后无法验收。

## 关于收敛

三轮设计——v1 的 12 层、v2 的 7 个升级、v3 的 5 个升级，总计 24 个"功能"，最终物理构件只有：
4 张表 + 几个评分公式 + 一组 Agent prompt。每一轮新想法都被同一个底座吸收，新增代价递减。
**这说明底座是对的，且设计已经收敛。** 从此每多一轮纸面升级的边际价值趋近于零，
而 Phase 0 每延迟一天都是真实损失——护城河是数据，数据只从记录的那天算起。

> 设计阶段到此结束。从这一刻起，价值在事件表里，不在设计文档里。
